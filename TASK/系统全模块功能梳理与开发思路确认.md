**FFmpeg转发实现**：
```python
# VIDEO/app/blueprints/camera.py:37
class FFmpegDaemon:
    """FFmpeg守护进程，管理RTSP→RTMP转发"""
    
    def start(device_id, rtsp_url, rtmp_url):
        cmd = [
            'ffmpeg',
            '-rtsp_transport', 'tcp',
            '-i', rtsp_url,
            '-c', 'copy',
            '-f', 'flv',
            rtmp_url
        ]
        subprocess.Popen(cmd)
```

**数据模型**：
```python
# VIDEO/models.py
class Device(db.Model):
    id = db.Column(db.String(100), primary_key=True)
    name = db.Column(db.String(100))
    source = db.Column(db.Text)         # RTSP地址
    rtmp_stream = db.Column(db.Text)    # RTMP推流地址
    http_stream = db.Column(db.Text)    # HTTP-FLV播放地址
    ip, port, username, password        # 设备连接信息
    mac, manufacturer, model            # 设备信息
    support_move, support_zoom          # PTZ能力
    enable_forward = db.Column(db.Boolean)  # 是否启用转发

## ✅ 开发思路确认

### 🎯 核心设计原则

#### 1. 模块职责清晰

| 模块 | 职责 | 不做什么 |
|------|------|---------|
| **AI模块** | 训练模型、导出模型、测试模型 | ❌ 不做实时视频流处理 |
| **VIDEO模块** | ONVIF管理、PTZ控制、截图 | ❌ 不做AI推理 |
| **TASK模块** | 实时AI推理、视频流处理 | ❌ 不做模型训练 |
| **DEVICE模块** | 业务逻辑、告警处理、权限管理 | ❌ 不做视频处理 |

#### 2. 功能复用策略

**✅ 直接复用**：
- DEVICE模块的告警接口：`POST /device/alarm`
- VIDEO模块的ONVIF发现
- Node-RED规则引擎
- 现有的用户权限体系
- 前端的摄像头管理页面

**🔄 扩展复用**：
- VIDEO的Device表：新增`ai_task_id`、`ai_enabled`字段
- 前端摄像头页面：新增"启动AI检测"按钮

**🆕 全新开发**：

    """FFmpeg守护进程，管理RTSP→RTMP转发"""

        cmd = [
            'ffmpeg',
            '-rtsp_transport', 'tcp',
            '-i', rtsp_url,
            '-c', 'copy',
            '-f', 'flv',

        ]
        subprocess.Popen(cmd)
