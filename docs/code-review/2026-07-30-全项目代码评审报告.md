## 一、总体结论

项目整体结构清晰（八大模块边界明确、`*-api`/`*-biz` 拆分干净、注释以中文为主、风格大体统一），但原始版本的**安全防线确实是最大短板**：存在多条可直达 RCE 的未鉴权链路，且多份真实凭据已进入 Git 历史。其次是**巨型文件/上帝函数**在各语言侧普遍存在（Java 9605 行、Python 4950 行、Vue 3431 行、C++ 单函数 290 行），核心业务测试覆盖不足。

再次复核确认原报告方向正确，但原“10 项 P0”同时存在**漏报、过度定级和关闭状态误判**：

1. **漏报的 P0**：iot-sink 可提交任意 JavaScript，原沙箱开放 HostAccess 且无超时；iot-device 暴露动态 Java 编译执行；iot-device、iot-dataset、iot-sink、iot-visualize、iot-node 与 iot-gb28181 共六个模块曾存在裸 `/** permitAll`；公共认证过滤器曾信任调用方可伪造的 `login-user` 头；NODE `/workload/deploy` 可直接执行下发命令。
2. **原 P0 过度定级**：TaskManager 只能拉起固定 TASK 可执行文件，原证据可确认“未鉴权控制 + INI 注入”，但不能单独证明任意 OS 命令执行，修正为 P1（若 TASK 配置链另有可利用执行点则升级 P0）；APP Promise 悬挂是 P1 可用性 bug；客户端 AES 内置密钥是 P1 设计缺陷并纳入凭据泄露事件；`set_permanent_token.sh` 是危险运维工具和硬编码凭据载体，不是独立认证绕过。
3. **错误证据修正**：LLM 两处 `v-html` 在插入自有标签前已转义 `&<>`，当前证据不足以确认直接 XSS；崩溃日志受 `hs_err_pid*` 忽略且未发现进入历史；实际入库备份为 `WEB/.env.development.bak`，不是 APP。
4. **关闭状态误判与整改结果**：点名的 12 份顶层运行时环境/备份文件及 4875 个 `deploy-packages/` 文件虽已从当前暂存索引移除（待提交），第三轮复扫又发现 8 个 FUXA 运行库/配置、Milvus Lite 人脸向量库、SQL 中的 webhook 凭据与 17325 行运行态日志/Token 数据、企业微信联调 Secret、公开前端地图 Key、带签名参数的文档图片 URL 以及 pnpm/VS Code/产测/文档生成物。DEVICE 侧初次复扫在 80 个 YAML 中发现 240 个明文凭据配置位点；将用户名、URL userinfo/query 和 Compose 字面量纳入后，整改前基线扩展为 386 项。本轮已把 101 份 DEVICE 主配置 YAML 和对应 Compose 的凭据改为环境变量契约，并加入可重复门禁；这解决的是当前源码继续扩散问题，不会撤销历史泄露。

**当前状态**：已确认的默认可达 RCE 执行链已在本工作区封堵，并补充针对性回归测试；六个 DEVICE 模块不再全局放行。已实现的 46 个 `/rpc-api/**` 映射由公共安全层统一校验 `X-Iot-Rpc-Token`，Feign 只对 RPC 路径注入受管令牌，Gateway 会清除外部伪造头并在访问令牌校验请求中注入受管令牌；`from-source: inner` 不再构成认证依据。iot-device EMQX webhook、iot-message 内部查询和 GB28181 媒体回调继续使用各自独立服务令牌。12 份顶层运行时环境/备份文件、6 份 TASK 摄像头联调 INI、8 个 FUXA 运行文件、Milvus Lite 人脸库、生成态文件及 `deploy-packages/` 已从当前索引移除（待提交）并保留在本机。仓库级凭据/运行时文件门禁当前扫描 7463 个受跟踪文本文件且 0 项违规，DEVICE 三种部署形态可静态展开且全 Reactor 编译成功。**凭据 P0 仍未关闭**：刷新 origin 后，扩展清理集合为 27 条路径、命中 96 个唯一历史提交（路径命中数，不代表每个提交都含有效秘密）；21 条整路径规则已在覆盖 927 个提交的独立镜像中演练为 0 残留，但 6 条必须保留的文件仍需基于已轮换旧值做内容级替换。已暴露凭据尚未轮换，本工作区尚未提交、推送、部署或做真实凭据下的服务连通性与线上验证。内部 RPC 生产令牌也尚未生成、下发和随容器协调重建，未做直连服务端口的错误/缺失令牌负向探测。任何源码检查通过或镜像演练成功都不能表述为“生产风险已解除”。

## 三、跨模块共性问题

### 1. 安全防线依赖部署层、代码层裸奔（系统性）
- AI:5000 与 VIDEO 多个管理 Blueprint 仍依赖网关/nginx 隔离；VIDEO `algorithm_task.py:23-895` 的任务增删启停、后处理初始化/切换均无 Blueprint 级本地认证。DEVICE 普通业务请求现已恢复认证，公共过滤器不再信任调用方可伪造的 `login-user` 头；46 个已实现 `/rpc-api/**` 映射现由公共安全层统一校验内部服务令牌（`YudaoWebSecurityConfigurerAdapter.java:130-131`），源码静态复扫的 RPC `permitAll` 为 0。Feign 仅为 RPC 路径注入，Gateway 先移除外部 `login-user`/内部令牌头再为自身 WebClient 调用注入；Servlet 缺失/错误/未配置返回 403，Gateway 内部令牌未配置或依赖异常返回 503，普通用户令牌无效仍为 401。当前只证明源码和静态配置，尚未用生产令牌重建 11 个容器或验证直连服务端口。Druid 与非健康 Actuator 端点现要求管理员，健康端点继续公开；GB28181 的 42 个业务控制器仍基本没有方法级角色授权，普通 WVP 用户的横向权限仍需单独梳理。
