 4.2 3 分钟版本

各位领导好，yFeiEye 是面向司法监管场景的智能视频与生理急症闭环平台。

我们理解监管场景里的风险处置，不是单纯做一个视频告警，也不是只展示几个生命体征指标。真正的业务闭环包括：异常被发现后，能否确认对应的在押人员；警务人员是否接收、到场、处置；红色急症是否触达医务并完成复测；关闭前证据链、责任链和审批链是否完整；事后能否审计复盘。

yFeiEye 在现有视频接入、算法任务、告警通知、截图录像、权限审计能力上，进一步补齐统一事件中心和闭环处置能力。系统可以把视频行为异常、生理风险、同帧关联和人工确认统一进入事件中心，形成事件状态机、动作队列、处置记录、医务复测、证据链和关闭校验。

在身份方面，我们不会简单把人脸、床位、点位或同帧关联直接当成个人事件身份，而是以监管系统人员台账或业务确认后的在押人员编号作为可信 `person_id`。这能避免低可信场景下误建个人风险事件。

在医务闭环方面，平台优先支持真实医务适配器，也允许现场条件不足时通过人工替代闭环完成业务处理。但系统会明确区分真实接口成功、人工完成、人工签字、模拟演示、客户阻断和未 ready 跳过，不把这些混成一个成功率。

这套机制适合监舍、隔离点位、重点人员点位、指挥中心值班处置等场景。它的目标不是多发一条告警，而是让每一次风险发现都有响应、有处置、有复测、有证据、有审计。

 4.3 5 分钟版本

各位领导好，今天给大家介绍 yFeiEye 司法AI智能监控平台。

监管场所的信息化建设已经有大量视频、门禁、告警和通知系统，但在实际处置中，经常会遇到几个问题。第一，系统发现了异常，但不清楚是否真正对应某个在押人员。第二，告警推送出去了，但警务人员是否确认、是否到场、是否处理，系统里不一定形成闭环。第三，涉及生理急症时，医务人员是否复测、复测结果是什么、是不是误报，也需要清晰记录。第四，项目验收时，真实接口成功、人工处理、模拟演示和客户现场未 ready 往往容易混在一起。第五，事后追溯时，视频、截图、体征、处置、复测和审计记录分散在不同地方，复盘成本高。

yFeiEye 的设计重点，就是把“告警提醒”升级为“事件闭环”。在平台里，视频告警、生理样本、行为事件和人工确认不会只停留在告警列表，而是进入统一事件中心。事件中心负责状态流转、动作派发、责任链、证据链和关闭校验。

我们把闭环拆成几个关键步骤。第一步，系统从视频算法、上游红外/近红外/热成像设备或厂商 SDK 获取输入。第二步，形成告警候选、生理样本和质量标签。第三步，通过监管系统人员台账或业务确认编号绑定可信 `person_id`。第四步，符合条件的风险进入事件中心。第五步，系统同步派发警务人员确认处理、医务复测和值班领导关注动作。第六步，警务人员回填现场处置，医务人员回填复测指标、医学判断、误差原因和 SOP 结果。第七步，系统检查动作、复测、证据、责任链和 readiness 状态，符合条件后才能关闭。最后，审计人员可以复盘全过程。

这里有几个重要边界。人脸识别、床位绑定、点位绑定和同帧 `correlation_id` 只能作为身份候选，不能单独生成个人生理事件。通知发送成功也不能代表医务复测完成。人工签字可以证明业务处理完成，但不能统计为真实接口成功。模拟演示能展示流程，但不能当成生产成功率。

从展会演示角度，我们可以现场展示一条链路：视频画面触发异常告警，系统进入事件中心，警务人员确认处理，医务人员完成复测，事件证据链自动归档，最后系统执行关闭校验并生成报表。观众能看到的不只是一个告警弹窗，而是一套监管责任闭环。

yFeiEye 的价值不是替代监管制度，而是把制度要求固化到系统流程里，让风险发现更及时、处置过程更清晰、医务复测更规范、审计复盘更有据可查。

 7. 展会问答口径

 Q1：这个方案是不是只做视频告警？

不是。视频告警是输入，事件闭环才是重点。yFeiEye 会把告警进入统一事件中心，关联责任人、动作队列、处置记录、复测记录、证据链和关闭校验。

 Q2：是否支持真实医务闭环？

方案优先支持真实医务适配器，包括医务触达、回执和复测回填。若客户现场暂时不具备接口、账号、班次或网络条件，也可以通过人工替代闭环完成业务处理，但系统会明确标记为 `manual_completed` 或 `manual_signed`，不会统计为 `real_success`。

 Q3：如果现场暂时没有医务系统接口，能不能验收？

可以先按人工替代闭环演示和验收业务处理过程，但验收报告必须区分真实接口成功、人工完成、人工签字、模拟、客户阻断和未 ready 跳过。这样既能跑通现场处置，又不虚报接口能力。

 Q4：误报怎么处理？

误报不会被简单删除。医务或复测角色需要回填复测指标、判断结论和误差原因，事件进入关闭校验后保留证据链，误差原因可沉淀到治理入口，用于后续点位整改、模型优化和规则调整。

 Q5：是否依赖人脸识别？

不单独依赖人脸。人脸、床位、点位和 `correlation_id` 都可以作为身份候选证据，但不能单独生成个人生理事件。个人事件需要监管系统人员台账或业务确认后的在押人员编号作为可信 `person_id`。

 Q6：如果身份不可信，系统会怎么做？

身份不可信时，不生成个人生理事件，不写入个人基线。系统会进入匿名质量统计或人工复核队列，避免把低可信信号误绑定到具体人员。

 Q7：系统如何避免“通知成功就算处理完成”？

yFeiEye 把通知、接收、现场处置、医务复测和关闭校验分成不同状态。通知成功只是动作状态之一，不能替代警务处理、医务复测和证据链闭合。

 Q8：是否支持审计复盘？

支持。事件关闭后，审计人员可按权限查看事件状态、动作记录、视频截图、录像片段、生理样本、复测记录、审批记录、导出记录和操作日志。

 Q9：是否能和现有视频、门禁、监管平台集成？

方案定位是基于现有视频接入、算法任务、告警通知、权限审计等能力进行监管闭环升级。具体集成范围需要根据客户现场的视频平台、人员台账、医务系统、网络策略和数据接口条件评估。

 Q10：生理监测是不是必须自研算法？

 优先对接上游红外、近红外、热成像设备或厂商 SDK 输出，由 yFeiEye 统一样本契约、质量标签、模型或设备版本和 readiness 校验。自研 worker 可以作为并行能力、兜底能力或后续替换路线，不阻塞第一条闭环落地。

 Q11：心理辅助或健康画像是否会作为监管定性？

不会。心理辅助和健康画像属于后续辅助运营能力，不作为 V1-P0 的处罚、诊断或监管定性依据。相关输出必须保留 `not_standalone_determination` 口径和权限隔离。

 Q12：展会现场最推荐演示哪条链路？

推荐演示“视频告警 -> 可信身份确认 -> 事件中心 -> 警务人员确认处理 -> 复测回填 -> 关闭校验 -> 证据链审计”。这条链路最能体现从告警提醒到监管闭环的差异。

 8. 现场物料短句库

 8.1 展板短句

- 告警只是开始，闭环才是价值。
- 让每一次异常处置有状态、有责任、有证据。
- 从视频发现到警务确认，从复测回填到审计复盘。
- 不把通知成功当处置完成。
- 不把身份候选当可信身份。
- 不把人工处理、模拟演示和真实接口成功混为一谈。

 8.2 销售强调语

- 我们解决的是监管风险处置闭环，不是单点算法展示。
- 平台把制度要求沉淀到事件状态和关闭校验里。
- 现场条件未 ready 可以先人工闭环，但报表必须诚实区分。
- 证据链不是几张截图，而是从发现到关闭的全过程材料。

 8.3 客户价值短句

- 对一线：任务更明确。
- 对指挥：状态更清楚。
- 对医务：复测有留痕。
- 对领导：风险可追踪。
- 对审计：事后可复盘。
