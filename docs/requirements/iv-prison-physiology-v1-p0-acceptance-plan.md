# 监狱生理监测 V1-P0 闭环验收方案

状态：草案  
适用范围：监狱/看守所单所试点的 V1-P0 红色生理急症闭环  
上游依据：`docs/requirements/supervision-event-closure-v1-requirements.md`、`docs/requirements/iv-physiology-v1-requirements-draft.md`、`CONTEXT.md`、`docs/adr/`

前置条件：监管事件处置闭环 V1 的 P0 能力已具备，即告警可进入监管事件、处置任务可派发/接收/处理/复核/关闭、关闭校验和证据链可审计。生理监测 P0 验收只验证红色生理急症如何接入该公共闭环。

## 1. 验收目标

V1-P0 只验收一条可运行、可解释、可审计的红色生理急症闭环。

验收链路为：

`上游生理输入 -> 生理样本 -> 质量/readiness 检查 -> 可信 person_id -> 生理事件 -> 事件中心 -> 医务动作/干警动作/领导关注 -> 医务复测 -> 关闭校验 -> 证据链归档 -> 报表区分`

V1-P0 不验收长期健康画像、完整心理辅助运营、完整模型治理平台和全监区趋势运营，但必须预留敏感数据权限、审计、readiness 和 `not_standalone_determination` 口径。

## 2. P0 验收边界

### 2.1 必须验收

1. 一个高危点位完成生理设备或厂商 SDK 接入。
2. 系统能生成统一 `Physiology Sample`，包含来源、点位、时间窗、指标、质量标签、置信度、模型或设备版本。
3. 只有可信 `person_id` 才能生成个人生理事件。
4. 红色生理急症必须进入统一事件中心，不得只停留在 `Alert` 列表。
5. 红色生理急症必须同时触发医务动作、监区干警动作和值班领导关注动作。
6. 医务人员必须回填复测记录，或形成合规的无法复测记录。
7. 事件关闭前必须通过动作、复测、证据、责任链和 readiness 校验。
8. 报表必须区分真实接口成功、人工完成、人工签字、模拟、客户阻断和未 ready 跳过。

### 2.2 暂不验收

1. 全监区、全点位规模化上线。
2. 长期健康画像和群体趋势运营。
3. 心理辅助复核完整工作台。
4. 生理模型冠军-挑战者、灰度、影子模式的完整运营。
5. 自研生理 worker 替代上游设备或厂商 SDK 的完整算法闭环。

### 2.3 不得降级

1. 不得把通知发送成功视为医务复测完成。
2. 不得把 `FacePerson.id`、床位绑定、点位绑定或 `correlation_id` 单独视为可信 `person_id`。
3. 不得把人工替代、模拟适配器或客户阻断统计为 `real_success`。
4. 不得让行为事件覆盖、降级或吞掉红色生理急症。
5. 不得在无证据链、无责任链或无关闭校验的情况下关闭红色事件。

## 3. 监狱角色责任链

| 角色 | P0 责任 | 必须留痕 | 超时/异常升级 |
| --- | --- | --- | --- |
| 监区值班民警 | 接收红色急症，现场确认在押人员状态，执行初步处置 | 接收时间、到场时间、处置说明、现场结果 | 未接收或未到场时升级监区值班长 |
| 监区值班长 | 协调现场处置，确认干警动作是否完成 | 审核意见、升级记录、关闭前确认 | 现场无法确认或处置冲突时升级指挥中心 |
| 指挥中心值班员 | 监督事件流转、协调跨角色动作、处理超时升级 | 调度记录、催办记录、升级记录 | 医务或监区超时后升级带班领导 |
| 医务人员 | 接收医务复测任务，完成体征复测和医学判断 | 复测指标、判断结论、误差原因、SOP 结果、附件 | 无法复测时提交原因并触发审批 |
| 带班领导 | 关注红色急症、审批重大异常或无法复测关闭 | 审批意见、审批时间、责任确认 | 对重大异常要求继续处置或复核 |
| 审计/督察人员 | 事后复盘事件闭环、导出证据、检查报表口径 | 查看记录、导出审批、导出记录 | 发现违规关闭或统计混算时退回整改 |

## 4. 红色急症状态机

### 4.1 事件状态

| 状态 | 含义 | 可进入条件 | 可退出条件 |
| --- | --- | --- | --- |
| `candidate` | 生理样本或告警候选已产生，但尚未形成个人事件 | 收到上游生理输入或算法告警 | 身份和质量通过后建事件；否则进入匿名质量统计或人工复核 |
| `identity_pending` | 身份证据不足，等待业务确认 | 只有身份候选，无可信 `person_id` | 绑定可信 `person_id` 后进入 `created`；超时后进入匿名质量统计 |
| `created` | 个人生理事件已创建 | 可信 `person_id`、质量和规则通过 | 分级为红色后进入 `dispatched` |
| `dispatched` | 医务、干警和值班领导动作已生成 | 动作队列创建成功 | 有角色接收后进入 `accepted`；超时进入 `escalated` |
| `accepted` | 至少一个责任角色已接收 | 医务或干警动作被接收 | 现场处置开始后进入 `on_site_handling` |
| `on_site_handling` | 现场核查和处置中 | 干警到场或指挥中心确认处置中 | 医务复测开始后进入 `medical_recheck` |
| `medical_recheck` | 医务复测中或等待复测记录 | 医务任务已创建并被处理 | 复测完成进入 `recheck_completed`；无法复测进入 `unable_to_recheck_review` |
| `unable_to_recheck_review` | 无法复测原因待审批 | 医务或现场提交无法复测原因 | 审批通过后进入 `pending_close_check`；审批驳回后回到 `medical_recheck` |
| `recheck_completed` | 医务复测已回填 | 有复测记录、医学判断和 SOP 结果 | 进入 `pending_close_check` |
| `pending_close_check` | 等待系统关闭校验 | 动作、复测或无法复测审批已齐备 | 校验通过进入 `closed`；不通过进入 `rework_required` |
| `rework_required` | 关闭校验不通过，需补充材料 | 缺动作、缺复测、缺证据或责任链断点 | 补齐后回到 `pending_close_check` |
| `closed` | 事件闭环关闭 | 关闭校验通过 | 只允许审计查看、导出或复盘 |

### 4.2 动作状态

| 状态 | 含义 | 统计口径 |
| --- | --- | --- |
| `pending` | 动作已创建，未触发 | 不计成功 |
| `sent` | 通知或接口请求已发送 | 不等于复测完成 |
| `acknowledged` | 责任人或外部系统已确认收到 | 不等于业务完成 |
| `real_success` | 真实接口或真实医务流程成功并有回执 | 可计入真实接口成功 |
| `manual_completed` | 人工替代闭环完成并有记录 | 只计人工完成 |
| `manual_signed` | 人工签字确认完成 | 只计人工签字 |
| `timeout` | 超时未收到接收或回执 | 计入超时 |
| `blocked_by_customer` | 客户现场接口、网络、账号、制度或人员阻断 | 计入客户阻断 |
| `skipped_not_ready` | readiness 未具备，跳过真实接口 | 计入未 ready |
| `simulated` | 演示或联调用模拟通道完成 | 不得计入生产成功 |

### 4.3 关闭校验

红色生理事件关闭前必须同时满足：

1. 有可信 `person_id` 或合规的非个人事件降级记录。
2. 有红色事件分级依据和生理样本快照。
3. 医务动作、干警动作和值班领导关注动作均有最终状态。
4. 有医务复测记录，或有无法复测原因和审批记录。
5. 有现场处置说明或无法处置说明。
6. 证据链包含指标、质量、时间窗、点位、事件规则、动作记录、医务记录和审计记录。
7. readiness 状态和动作统计口径已固化。
8. 关闭人具备 `events:close` 权限，关闭操作进入审计。

## 5. SOP 主流程

1. 高危点位完成设备标定、在线检查和分析时段配置。
2. 上游红外、近红外、热成像设备或厂商 SDK 输出生理结果。
3. yFeiEye 归一化为 `Physiology Sample`。
4. 系统计算质量标签：遮挡、运动伪影、热源干扰、设备未标定、有效采样占比。
5. 系统尝试绑定可信 `person_id`。
6. 无可信身份时，不生成个人生理事件，进入匿名质量统计或人工复核。
7. 有可信身份且触发红色急症规则时，创建个人生理事件。
8. 事件进入统一事件中心，生成事件编号、状态机和证据链目录。
9. 动作队列生成医务动作、干警动作和值班领导关注动作。
10. readiness 为 `ready` 时优先走真实医务适配器。
11. readiness 为 `manual_required` 时走人工替代闭环，并记录原因。
12. 监区值班民警接收并执行现场核查。
13. 医务人员接收复测任务并回填复测指标、医学判断、误差原因、SOP 结果和附件。
14. 指挥中心监督超时、催办和升级。
15. 系统执行关闭校验。
16. 关闭后，复测结论、误差原因和低可信原因进入最小治理入口。
17. 审计员可按权限查看事件、证据链、导出记录和统计口径。

## 6. 异常分支

### 6.1 身份不可信

触发条件：只有人脸匹配、床位绑定、点位绑定或 `correlation_id`，没有监管台账或业务确认的在押人员编号。

处理规则：

1. 不创建个人生理事件。
2. 进入匿名质量统计或人工身份复核。
3. 可保留身份候选证据，但不得写入个人基线。
4. 若人工复核确认可信 `person_id`，再按事件创建规则补建或关联事件。

验收不通过条件：系统直接用身份候选生成个人事件。

### 6.2 低质量窗口

触发条件：ROI 丢失、遮挡、强运动、热源干扰、厚被遮挡、设备未标定或有效采样占比不足。

处理规则：

1. 不生成个人生理事件。
2. 不写入个人基线。
3. 记录低可信原因。
4. 进入点位整改、设备标定或匿名质量统计。

验收不通过条件：低可信窗口进入个人风险事件或个人基线。

### 6.3 医务真实适配器不可用

触发条件：真实医务接口、医务账号、班次、网络、回执或回填能力未 ready。

处理规则：

1. readiness 标记为 `manual_required` 或 `skipped_not_ready`。
2. 系统创建人工替代任务。
3. 人工电话、对讲、现场通知或签字完成后记录为 `manual_completed` 或 `manual_signed`。
4. 报表不得计入 `real_success`。

验收不通过条件：人工完成被统计成真实接口成功。

### 6.4 医务或干警超时

触发条件：责任角色在配置时限内未接收、未到场、未复测或未回填。

处理规则：

1. 动作状态进入 `timeout`。
2. 系统催办责任人。
3. 升级监区值班长、指挥中心或带班领导。
4. 超时记录进入证据链和报表。

验收不通过条件：超时未升级，或事件仍可直接关闭。

### 6.5 复测为误报

触发条件：医务复测判断非真实异常。

处理规则：

1. 医务人员回填复测指标和误差原因。
2. 事件可进入关闭校验，但必须保留原始生理样本和判定依据。
3. 误差原因进入最小治理入口。
4. 报表区分真实异常、误报、无法复测。

验收不通过条件：误报事件删除证据，或不沉淀误差原因。

### 6.6 客户现场阻断

触发条件：客户未提供接口、账号、班次、制度确认、网络策略或现场负责人。

处理规则：

1. readiness 标记为 `blocked_by_customer`。
2. 记录阻断材料和责任说明。
3. 可走人工替代闭环完成业务处理。
4. 验收报告必须明确该项不是系统真实接口成功。

验收不通过条件：客户阻断被写成系统成功。

### 6.7 模拟环境

触发条件：本地联调、演示 profile 或模拟医务适配器。

处理规则：

1. 动作状态标记为 `simulated`。
2. 可用于演示流程，不可作为生产验收成功。
3. 报表和验收结论必须单独列示。

验收不通过条件：模拟成功被计入生产真实成功。

## 7. 验收脚本

### 7.1 脚本 A：正常红色急症闭环

输入条件：

1. 高危点位在线且已标定。
2. 上游设备输出红色生理异常样本。
3. 监管台账或业务系统可提供可信 `person_id`。
4. 医务适配器 readiness 为 `ready`，或人工替代配置已 ready。

操作步骤：

1. 注入或等待红色生理样本。
2. 查看系统生成的 `Physiology Sample`。
3. 查看个人生理事件和事件中心状态。
4. 医务人员接收任务并回填复测。
5. 监区值班民警回填现场处置。
6. 系统执行关闭校验。
7. 审计员查看证据链和报表口径。

期望结果：

1. 事件状态从 `candidate` 流转到 `closed`。
2. 医务、干警、领导动作均有最终状态。
3. 证据链可复盘。
4. 报表正确记录 `real_success` 或人工替代状态。

不通过条件：

1. 只生成告警，没有事件中心记录。
2. 通知成功后直接关闭。
3. 缺医务复测或无法复测审批仍关闭。

### 7.2 脚本 B：身份不可信降级

输入条件：

1. 生理样本触发红色规则。
2. 只有人脸候选、床位候选或 `correlation_id`，没有可信 `person_id`。

操作步骤：

1. 注入样本。
2. 查看事件创建结果。
3. 查看匿名质量统计或人工复核队列。

期望结果：

1. 不生成个人生理事件。
2. 保留身份候选证据。
3. 记录匿名质量统计或人工复核任务。

不通过条件：

1. 直接生成个人生理事件。
2. 写入个人基线。

### 7.3 脚本 C：低质量窗口保护

输入条件：

1. 点位在线。
2. 样本存在遮挡、强运动、热源干扰或设备未标定。

操作步骤：

1. 注入低质量样本。
2. 查看质量标签和处理结果。

期望结果：

1. 标记低可信原因。
2. 不生成个人事件。
3. 不写入个人基线。
4. 进入匿名质量统计或点位整改。

不通过条件：

1. 低可信数据进入个人事件或基线。

### 7.4 脚本 D：真实医务适配器不可用，人工替代闭环

输入条件：

1. 红色生理事件可生成。
2. 医务适配器 readiness 为 `manual_required` 或 `skipped_not_ready`。
3. 人工替代配置可用。

操作步骤：

1. 触发红色事件。
2. 查看动作队列 readiness 判断。
3. 由人工完成通知、复测或签字。
4. 关闭事件并查看报表。

期望结果：

1. 事件可完成业务闭环。
2. 动作状态为 `manual_completed` 或 `manual_signed`。
3. 报表不计入 `real_success`。

不通过条件：

1. 人工替代被算作真实接口成功。
2. 无人工留痕仍关闭。

### 7.5 脚本 E：医务超时升级

输入条件：

1. 红色事件已创建。
2. 医务人员未在规定时限内接收或回填。

操作步骤：

1. 触发红色事件。
2. 等待超过医务接收或复测时限。
3. 查看动作状态、催办和升级记录。

期望结果：

1. 医务动作进入 `timeout`。
2. 系统升级指挥中心或带班领导。
3. 事件不能直接关闭。

不通过条件：

1. 超时无记录。
2. 未复测且无审批即可关闭。

### 7.6 脚本 F：复测为误报

输入条件：

1. 红色事件已创建。
2. 医务复测判断非真实异常。

操作步骤：

1. 医务人员回填复测指标、医学判断和误差原因。
2. 关闭事件。
3. 查看治理入口和报表。

期望结果：

1. 事件可关闭，但证据链保留。
2. 误差原因进入治理沉淀。
3. 报表计为误报或复测非异常，不删除原事件。

不通过条件：

1. 误报事件被物理删除。
2. 无误差原因沉淀。

### 7.7 脚本 G：客户现场未 ready

输入条件：

1. 客户未提供医务接口、账号、班次或网络条件。
2. 红色事件仍需业务闭环。

操作步骤：

1. 执行 readiness 检查。
2. 触发红色事件。
3. 走人工替代闭环。
4. 查看验收报表。

期望结果：

1. readiness 标记 `blocked_by_customer` 或 `manual_required`。
2. 事件可通过人工替代完成业务闭环。
3. 报表明确不计真实接口成功。

不通过条件：

1. 客户阻断被写成系统真实成功。

### 7.8 脚本 H：行为与生理同时触发

输入条件：

1. 同一时间窗存在倒地等行为事件。
2. 同一可信 `person_id` 或同一点位出现红色生理急症。

操作步骤：

1. 同时触发行为和生理输入。
2. 查看事件中心和融合关系。
3. 查看急症通道动作。

期望结果：

1. 行为事件和生理事件都保留。
2. 存在融合关系或冲突原因。
3. 红色生理急症不被行为事件覆盖或降级。

不通过条件：

1. 只保留行为事件。
2. 生理急症未触发医务动作。

## 8. 证据链要求

每个红色生理事件至少需要以下证据：

1. 生理样本快照：指标、时间窗、点位、来源、质量标签、置信度、模型或设备版本。
2. 身份证据：可信 `person_id` 来源、身份候选、业务确认记录。
3. 事件证据：规则命中、分级依据、事件状态变化。
4. 视觉证据：截图、录像片段或不可用原因。
5. 动作证据：医务、干警、领导动作状态和时间。
6. 医务证据：复测指标、医学判断、误差原因、SOP 结果、附件。
7. readiness 证据：真实接口、人工替代、模拟、客户阻断或未 ready 的判断。
8. 审计证据：查看、回填、关闭、导出、审批操作。

证据链缺关键材料时，不阻塞红色急症触达，但必须阻塞普通关闭，直到补齐或形成合规缺口说明。

## 9. 报表和统计口径

P0 报表至少区分：

1. 红色生理事件总数。
2. 已关闭事件数。
3. 待复测事件数。
4. 超时升级事件数。
5. 真实接口成功数：`real_success`。
6. 人工完成数：`manual_completed`。
7. 人工签字数：`manual_signed`。
8. 模拟完成数：`simulated`。
9. 客户阻断数：`blocked_by_customer`。
10. 未 ready 跳过数：`skipped_not_ready`。
11. 复测真异常数。
12. 复测误报数。
13. 无法复测审批数。
14. 身份不可信降级数。
15. 低质量窗口降级数。

报表不得只给一个“成功率”。若需要成功率，必须至少拆成真实接口成功率、人工闭环完成率、复测完成率和关闭校验通过率。

## 10. P0 通过标准

满足以下条件，P0 闭环可判定为通过：

1. 脚本 A、B、C、D、E、F、G、H 均可演练并留痕。
2. 正常红色急症能从样本进入事件中心，并完成医务复测和关闭。
3. 身份不可信和低质量窗口不会生成个人事件或个人基线。
4. 医务动作、干警动作和值班领导关注动作均有状态和责任人。
5. 关闭校验能拦截缺复测、缺动作、缺证据、缺责任链的事件。
6. 报表能区分真实接口成功、人工完成、人工签字、模拟、客户阻断和未 ready。
7. 审计员能复盘事件证据链和操作记录。
8. 心理辅助或健康画像相关输出没有作为 P0 判定依据。

## 11. P0 不通过条件

出现以下任一情况，P0 判定不通过：

1. 红色生理急症只进入 `Alert`，没有统一事件中心状态机。
2. 无可信 `person_id` 仍创建个人生理事件。
3. 低可信窗口写入个人基线。
4. 通知发送成功被当作医务复测完成。
5. 医务超时没有升级和审计。
6. 无复测记录或无法复测审批仍能关闭。
7. 人工替代、模拟或客户阻断被计入真实接口成功。
8. 行为事件覆盖或降级红色生理急症。
9. 缺少证据链仍可普通关闭。
10. 导出敏感证据没有权限和审计。

P0 验收前应准备：

1. 高危点位台账和标定记录。

3. `Physiology Sample` 样例数据。
4. 事件状态机和动作状态字典。
5. 医务复测表单或接口样例。
6. readiness 检查项清单。

9. 报表口径样例。
10. 八条验收脚本的演练记录。
