# 监管事件处置闭环 V1-P0 验收运行手册

来源：`docs/prd/supervision-event-closure-v1-prd.md`、`docs/prd/supervision-event-closure-v1-engineering-contract.md`
适用范围：任务 01-09 的 P0 验收

## 1. 验收原则

1. 告警仍然是线索，监管事件才是处置闭环。
2. 任何脚本都不能破坏现有告警列表、图片查看、录像查看、地图分布、清空告警和设备定位能力。
3. 事件关闭必须能解释责任链、处置记录、复核记录、关闭校验和证据链。
4. 失败脚本和权限拦截脚本与成功脚本同等重要。
5. 每条脚本必须记录输入、步骤、预期状态、预期证据、权限结果和不通过条件。

## 2. 验收前置条件

1. 已冻结 `docs/prd/supervision-event-closure-v1-engineering-contract.md`。
2. 已完成监管事件、处置任务、复核、关闭校验、证据链和权限的 P0 实现。
3. 已准备至少 3 个测试账号：指挥中心值班员、现场处理人、值班领导。
4. 如涉及生命安全或戒毒异常脚本，另准备医务人员或康复/心理人员账号。
5. 系统中至少存在一条可展示图片和录像的原始告警。

## 3. 普通告警闭环

输入：普通设备离线或普通视频告警，默认 L1。

步骤：

1. 指挥中心从告警列表进入告警详情。
2. 生成人工确认监管事件。
3. 派发现场处置任务。
4. 现场处理人接收任务。
5. 现场处理人填写处置说明和结果分类。
6. 指挥中心发起关闭校验。
7. 关闭校验通过后关闭事件。

预期结果：

- 事件状态依次出现 `created`、`dispatched`、`accepted`、`handling`、`pending_close_check`、`closed`。
- 任务状态依次出现 `pending`、`acknowledged`、`submitted`、`closed`。
- 证据链包含原始告警、处置任务、处置说明、关闭记录和操作日志。

不通过条件：

- 通知成功被当作处置完成。
- 未填写处置说明也能关闭。
- 原始告警被删除或被改写。

## 4. 生命安全事件闭环

输入：倒地、突发疾病或生理红色急症，默认 L4。

步骤：

1. 系统自动生成 L4 监管事件。
2. 指挥中心派发现场处置任务和医务复核任务。
3. 现场处理人接收并提交现场处置记录。
4. 医务人员提交复核记录。
5. 值班领导查看事件、处置和复核记录。
6. 系统执行关闭校验。
7. 值班领导关闭事件。

预期结果：

- L4 事件不能由普通处理人关闭。
- 缺医务复核时关闭校验失败。
- 关闭后证据链包含原始告警、现场处置、医务复核、领导关闭意见和操作日志。

不通过条件：

- 缺医务复核仍可普通关闭。
- 普通处理人可关闭 L4。
- 生命安全事件只停留在告警列表，没有生成监管事件。

## 5. 戒毒异常闭环

输入：戒断异常、康复训练异常或心理/行为异常，默认 L3。

步骤：

1. 系统按规则生成 L3 监管事件。
2. 指挥中心派发大队处置任务。
3. 大队民警提交现场处理记录。
4. 医务/康复人员提交辅助复核。
5. 值班领导确认关闭。

预期结果：

- 康复/心理复核记录进入证据链。
- 康复/心理输出只作为辅助复核，不单独作为惩戒或最终监管定性。
- L3 关闭需要领导确认。

不通过条件：

- 康复/心理记录被普通用户查看。
- L3 未经领导确认即可关闭。
- 辅助复核被系统标记为最终监管定性。

## 6. 驳回补充

输入：任意 L2 或 L3 监管事件。

步骤：

1. 现场处理人提交处置记录。
2. 复核人选择驳回。
3. 复核人填写驳回原因。
4. 事件进入 `rework_required`。
5. 现场处理人补充材料后再次提交。
6. 复核人通过。

预期结果：

- 驳回原因必填。
- 原始提交记录保留。
- 补充后事件可继续进入关闭校验。

不通过条件：

- 驳回不需要原因。
- 驳回覆盖原始处置记录。
- 返工后无法进入后续闭环。

## 7. 误报归档

输入：可确认为误报的普通告警。

步骤：

1. 指挥中心将告警生成为监管事件。
2. 指挥中心选择误报结果。
3. 填写误报原因。
4. 执行关闭校验。
5. 关闭事件。

预期结果：

- `close_result` 为 `false_alarm`。
- 误报原因必填。
- 原始告警、图片、录像和操作日志仍在证据链中。

不通过条件：

- 误报关闭删除原始告警。
- 无误报原因也能关闭。
- 误报不进入审计。

## 8. 关闭拦截

输入：缺责任人、缺处置说明、缺复核或缺关键证据的事件。

步骤：

1. 打开待关闭事件。
2. 发起关闭校验。
3. 查看硬拦截项和软提醒项。
4. 尝试普通关闭。

预期结果：

- 关闭校验返回 `failed`。
- 硬拦截项展示可读原因。
- 普通关闭失败。
- 事件保持未关闭状态。

不通过条件：

- 缺关键材料仍能关闭。
- 关闭失败没有原因。
- 关闭失败没有操作日志。

## 9. 权限隔离

输入：L3 或 L4 事件。

步骤：

1. 系统管理员尝试伪造处置记录。
2. 现场处理人尝试关闭 L3/L4。
3. 无敏感权限用户尝试查看医务、心理或康复证据。
4. 值班领导尝试关闭 L3/L4。
5. 督察/审计人员查看证据链。

预期结果：

- 系统管理员不能伪造业务处置、复核和关闭记录。
- 现场处理人不能关闭 L3/L4。
- 无敏感权限用户看不到敏感证据详情。
- 值班领导可按权限关闭高等级事件。
- 督察/审计人员可查看全链路，但不能修改处置过程。

不通过条件：

- 技术管理员能代填业务闭环。
- 普通处理人能关闭高等级事件。
- 敏感证据被普通权限暴露。

## 10. 现有告警图片和录像回放非回归

输入：已有告警列表中的一条带图片或录像的告警。

步骤：

1. 进入告警列表。
2. 打开告警图片。
3. 打开告警录像。
4. 切换地图分布。
5. 返回告警事件列表。
6. 如具备权限，点击生成监管事件。
7. 再次打开告警图片和录像。

预期结果：

- 图片查看行为与改造前一致。
- 录像播放行为与改造前一致。
- 地图分布正常显示。
- 清空告警按钮行为不被监管事件入口改变。
- 监管事件入口只是新增动作，不替换原有告警动作。

不通过条件：

- 图片按钮消失或不可用。
- 录像按钮消失或不可用。
- 地图分布无法加载。
- 生成监管事件后原告警无法查看。
