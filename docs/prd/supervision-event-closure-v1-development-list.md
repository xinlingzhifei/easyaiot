# 司法监管事件处置闭环 V1 开发列表

状态：建议拆分
来源：`docs/prd/supervision-event-closure-v1-prd.md`
拆分原则：先形成告警到监管事件的最小闭环，再接入生理急症、戒毒异常、报表和治理。

## 研发前置契约

开工前先冻结 `docs/prd/supervision-event-closure-v1-engineering-contract.md`。该文档是任务 01 的主要交付物，也是任务 02-09 的字段、接口、权限和规则种子依据。

## 总体顺序

1. 先确认事件中心归属、对象边界、字段字典、接口边界和 `Alert -> Event` 契约。
2. 先跑通一条普通告警从监管事件到处置关闭的闭环。
3. 再补齐等级、SOP、关闭校验、职责隔离、证据链和超时升级。
4. 最后接入生理红色急症、戒毒康复异常、报表治理和多场所差异化配置。

## V1-P0 开发切片

### 1. 监管事件中心边界与对象契约

类型：HITL
Blocked by：无

要交付：

- 明确 `Alert`、`Supervision Event`、`Disposal Task`、`Action`、`Evidence Chain` 的边界。
- 明确事件中心 owner 和跨 VIDEO、DEVICE/iot-message、WEB、iot-system 的契约。
- 明确不把处置闭环继续塞进 `Alert`。

验收标准：

- 有 `Alert -> Event` 契约。
- 有 P0 对象清单和状态语义。
- 有权限、审计、迁移边界说明。

### 2. 告警转监管事件规则

类型：AFK
Blocked by：1

要交付：

- 配置或内置告警来源、告警类型、是否生成事件、默认等级、责任链模板。
- 支持从现有告警列表或详情生成监管事件。
- 同一告警默认只能关联一个未关闭监管事件。

验收标准：

- 普通告警可人工确认生成事件。
- 倒地、突发疾病、生理红色急症等高危告警可自动生成事件。
- 已有关联事件时，页面进入“查看监管事件”而不是重复创建。

### 3. 监管事件模型与状态机

类型：AFK
Blocked by：1

要交付：

- 实现监管事件基础信息、类型、等级、来源告警、状态、责任单位、创建人和租户隔离。
- 实现事件状态流转和状态日志。

验收标准：

- 事件可创建、查询、查看详情。
- 状态变化进入时间线。
- 事件详情保留原始告警、设备、图片和录像入口。

### 4. 处置任务派发、接收和处理提交

类型：AFK
Blocked by：2, 3

要交付：

- 支持从事件派发处置任务。
- 支持责任人接收任务、填写到场时间、处置说明、现场结果和附件。
- 支持“我的待办”入口。

验收标准：

- 指挥中心能派发任务。
- 责任人能接收并提交处置结果。
- 任务状态和事件时间线同步更新。

### 5. 复核与退回补充

类型：AFK
Blocked by：4

要交付：

- 支持复核人通过或驳回处置结果。
- 支持医务、康复心理、领导等不同复核类型。
- 驳回必须填写原因并进入补充状态。

验收标准：

- 复核通过后进入关闭校验。
- 复核驳回后处理人可补充材料再提交。
- 复核记录进入证据链和时间线。

### 6. 关闭校验规则

类型：AFK
Blocked by：4, 5

要交付：

- 实现 L1-L4 关闭校验。
- 区分硬拦截、软提醒和例外审批。
- 关闭结果使用受控字典。

验收标准：

- 缺责任人、缺处置说明、缺复核或缺领导确认时不能关闭。
- 误报关闭保留原始告警和误报原因。
- L3/L4 只能由授权角色关闭或进入例外审批。

### 7. 证据链和事件时间线

类型：AFK
Blocked by：3, 4, 5, 6

要交付：

- 汇总原始告警、图片、录像、设备、点位、人员、任务、处置、复核、关闭和操作日志。
- 事件详情展示可审计时间线。

验收标准：

- 审计人员能复盘事件生命周期。
- 图片/录像仍复用现有存储和播放入口。
- 证据链缺口能影响关闭校验。

### 8. 职责隔离和数据权限

类型：AFK
Blocked by：3, 4, 5, 6

要交付：

- 区分调度权、处置权、医务复核权、康复心理复核权、领导关闭权、督察查看权和系统配置权。
- 敏感医疗、心理、康复内容使用单独数据权限。

验收标准：

- 系统管理员不能伪造处置、复核、关闭记录。
- 现场处理人不能关闭 L3/L4。
- 非授权用户不能查看敏感医务或心理详情。

### 9. P0 验收脚本和演练数据

类型：AFK
Blocked by：6, 7, 8

要交付：

- 准备普通告警、生命安全、戒毒异常、驳回补充、误报归档、关闭拦截和权限隔离脚本。
- 输出演练记录模板。

验收标准：

- 每条脚本都有输入、步骤、预期结果和不通过条件。
- 演练结果能映射到事件时间线和证据链。

## V1-P1 开发切片

### 10. 超时升级和催办

类型：AFK
Blocked by：4, 8

要交付：

- 支持接收、到场、处置、复核的时限配置。
- 超时后生成催办和升级记录。

### 11. 告警合并和重复告警归并

类型：AFK
Blocked by：2, 3

要交付：

- 支持同设备、同区域、同人员、同时间窗告警合并到同一事件。
- 重复告警可作为同一事件证据追加。

### 12. 生理红色急症接入

类型：AFK
Blocked by：6, 8；并依赖 `docs/prd/iv-prison-physiology-v1-prd.md`

要交付：

- 生理红色急症创建 L4 监管事件。
- 必须触发医务复核、现场处置和领导关闭规则。

### 13. 戒毒康复异常专项接入

类型：AFK
Blocked by：6, 8

要交付：

- 支持戒断异常、康复训练异常、心理/行为异常进入事件闭环。
- 康复/心理复核记录为辅助性质，不单独作为惩戒或最终监管定性。

### 14. 闭环统计和督察复盘

类型：AFK
Blocked by：7, 9, 10

要交付：

- 统计事件总数、闭环率、超时率、误报率、转重大事件数、无法确认审批数。
- 支持督察按事件类型、责任单位、等级、关闭结果复盘。

## 推荐首轮迭代

第一轮建议只做 1-9，完成后系统应能证明：

1. 告警不只是列表记录，而是能进入监管事件。
2. 监管事件能派发到人并形成处置记录。
3. 高风险事件能复核、驳回、补充和关闭校验。
4. 事件关闭有证据链、时间线和权限边界。
