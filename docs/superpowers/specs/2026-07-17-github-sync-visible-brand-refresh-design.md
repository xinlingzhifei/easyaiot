## 合并设计

### 1. 建立可恢复基线

在任何合并前记录当前提交和完整 Git 状态，并创建只指向当前提交的安全分支。安全分支只用于恢复，不改变当前工作树内容。

由于当前存在大量未跟踪产物，合并在独立 Git worktree 中完成。这样可以避免部署包和临时目录干扰冲突处理，同时保持原工作区原样。隔离 worktree 的目标分支从当前 `HEAD` 创建。

### 2. 使用普通三方合并

在隔离分支执行 `git merge --no-ff origin/main`。不使用 `-X ours` 或整树 `ours` 策略，因为这些策略会静默丢失远端修改。

自动合并成功的远端变更直接保留。41 个预期冲突按以下规则逐项解决：

1. 先比较共同基线、本地版本和远端版本。
2. 本地已有业务能力、兼容行为、修复和品牌实现不得被远端旧实现回退。
3. 远端新增字段、接口、MQTT 能力、部署改进和缺陷修复，只要不破坏本地行为就合入。
4. 同一职责出现两套状态源、定时器、重试器或配置时，不机械拼接；保留当前本地架构的单一职责实现，并把远端新增输入接入该实现。
5. README 多语言冲突保留远端新增内容，但最终统一可见品牌。

重点冲突域包括：

- 构建与部署脚本：保持本地缓存、镜像和运行时修复，并吸收远端麒麟部署及 IoT 安装改进。
- AI 与 VIDEO：保持本地模型、算法任务和运行修复，并吸收远端模型管理及部署变化。
- DEVICE MQTT：以远端新增上下行能力为输入，保留本地已修复的鉴权、事件和消息兼容行为。
- WEB：保持本地登录、播放、平台品牌和公共 URL 行为，并吸收远端设备、模型、产品和 IoT 页面更新。

### 3. 回写当前分支

隔离 worktree 内完成冲突解决和基础检查后创建合并提交。随后让当前分支快进到该合并提交；因为原工作区受跟踪文件干净且未跟踪路径无碰撞，此操作不会覆盖本地文件。

若合并或验证失败，当前分支保持不动，安全分支仍指向原始提交。不得用破坏性命令清理失败状态。

## 品牌替换设计

### 1. 必须替换的可见范围

- Vue、TypeScript、Java、Python、Shell、HTML 和 JSON 中实际展示给用户的标题、标签、菜单、提示、日志标题和默认品牌名。
- 登录页、仪表盘、设备、产品、模型、训练、节点及 APP 页面可见文案。
- 顶层 `README*`、公开部署文档、宣传文档和页面使用的示例文案。
- 被页面或文档引用且名称包含旧品牌的展示型文件。
- 页面加载的图片中肉眼可见的旧品牌文字。

### 2. 必须保护的运行契约

- 仓库地址和第三方链接。
- 已有接口 URL、路由兼容别名、环境变量名、容器及网络名。
- 文件系统路径、数据库对象、服务发现名称和存储键。
- 代码中的内部兼容 key，例如 APP 菜单内部键；其展示名称仍改为 `yFeiEye`。
- 当前本地分支已经使用的 `yFeiEye` 技术值，以本地代码为准，不被远端旧值回退。

品牌处理采用“可见内容替换 + 保护列表审计”，不执行不加区分的全仓库小写字符串替换。

### 3. 自动化残留契约

沿用并更新 `WEB/tests/visibleBrandingResidue.test.ts`：

- 扫描所有受跟踪文本文件及路径中的 `EasyAIoT` 和 `Easy AI Internet of Things`。
- 排除设计与实施计划自身的历史说明。
- 明确断言页面展示名为 `yFeiEye`。
- 明确断言需要保留的内部兼容键和本地技术值未被误改。

合并后先运行该测试得到真实残留清单，再按可见或运行契约分类处理，直至测试通过。

### 4. 图片审计

只检查被页面或公开文档实际引用的品牌图片。若图片含有可见的 `EasyAIoT`，仅替换品牌文字，保持尺寸、布局、颜色和其他内容不变；无旧品牌的图片保持字节不变。
