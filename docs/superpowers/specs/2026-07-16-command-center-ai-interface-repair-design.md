# 登录后指挥中心、AI 启动与接口失败修复设计

## 目标

把登录成功后的首页重做为“单画面聚焦型”视觉智能巡检指挥中心，并一次性修复首页告警接口 403、重复失败请求以及 AI 无法从空任务状态启动的问题。

## 已确认决策

- 首页采用单画面聚焦布局：左侧设备与通道，中间单路实时视频，右侧实时告警。
- 顶部展示平台名称、关键运行指标、系统健康状态和更新时间。
- “管理后台”入口固定保留在右上角，继续使用现有路由解析与大屏遮罩释放逻辑。
- AI 开关仍是首页唯一的识别入口；开启后必须真正创建或复用后台任务、启动算法并进入告警链路。
- 采用端到端耐久修复，不依赖服务器手工补建一次性任务。
- 保留现有视频播放、国标通道同步、AI 流回退、页面切换后视频恢复和告警回放能力。

## 已验证根因

### 1. 首页告警接口 403

线上访问日志显示登录后的首页持续请求：

- `GET /video/alert/statistics`
- `GET /video/alert/page`

两者均返回 HTTP 403。VIDEO 的持久化媒体访问审计给出的稳定原因是：

```text
decision=denied
reason=action_permission_denied
authType=user_token
tenantPresent=true
cameraPresent=false
```

代码链路进一步确认：

- VIDEO 以 `alert_read` 动作调用 DEVICE 的 `/system/auth/media-permission-check`。
- DEVICE 的 `MEDIA_ACTIONS` 当前没有 `alert_read`，因此在摄像头校验前直接拒绝。
- 首页请求没有携带当前摄像头 ID；即使动作被加入白名单，下一步仍会因缺少摄像头范围而拒绝。
- `ConfiguredReviewCameraPermissionResolver` 没有安全的内建动作到权限映射；缺少外部配置时所有动作都会 fail closed。

因此修复必须同时覆盖动作、权限映射和当前摄像头范围，不能只在前端隐藏错误。

### 2. 告警列表重复失败请求

`useDashboardData.ts` 每 5 秒刷新一次，但调用 `queryAlarmList()` 时没有传 `{ polling: true }`。告警列表因此没有采用已定义的“大屏轮询关闭 GET 重试”选项，单次 403 会继续触发默认重试，形成同一轮刷新中的多次失败请求。

### 3. AI 从空任务状态启动失败

线上 `algorithm_task` 表当前为空。`startDashboardGuardTask()` 只会：

- 复用已有运行任务；或
- 从已有实时任务复制模型配置后创建首页任务。

当没有任何实时任务时，它会抛出“没有带模型的实时任务”，所以首页 AI 无法从零启动。

### 4. 告警类别约束互相矛盾

模型字段和 `alert_class_filter.py` 已明确规定：告警类别为空时，任意检测结果都可以触发告警。但 `algorithm_task_service.py` 的创建与更新校验又禁止“启用告警且类别为空”。这会阻断自动创建默认首页任务。

## 首页信息架构

### 顶部栏

- 左侧：平台名称与“实时监控 · AI 识别 · 告警联动”说明。
- 中部：播放路数、今日告警、AI 任务状态、接口健康状态。
- 右侧：最近更新时间、日期、“管理后台”按钮。
- 管理后台按钮继续保留 `data-testid="monitor-admin-entry"`，点击后释放全屏遮罩并进入现有后台目标路由。

### 指标带

在三栏主体上方放置四个紧凑指标：

- 在线设备
- 播放中
- AI 模型
- 今日告警

指标只显示真实接口结果；加载、无数据、部分失败分别显示检查中、`—` 和明确异常状态，不用假数字填充。

### 左栏：设备与通道

- 保留现有设备树、国标通道展开、搜索与后台同步能力。
- 选中叶子设备后同时更新：主视频、告警数据范围、统计数据范围和 AI 任务范围。
- 移除重复的四块大统计卡，给设备树更多垂直空间。

### 中栏：单画面实时监控

- 首页固定以单路主画面为视觉中心，不展示四宫格和布局方案工具条。
- 多画面与布局预设代码继续保留给其他监控场景，不在首页删除底层能力。
- 主画面顶部显示设备名称、位置、原始流/AI 流状态和 AI 开关。
- AI 状态必须区分：未启用、启动中、运行中、原始流回退、启动失败。
- 告警录像保留在主画面下方，但降低高度，避免挤压实时画面。

### 右栏：实时告警

- 显示当前摄像头范围内最近 7 条告警。
- 保留告警图片、类型、处置状态、设备和时间。
- 点击后继续调用现有告警录像播放流程。
- 空状态明确显示“当前设备暂无告警”；接口失败显示具体失败原因与手动重试入口。

### 视觉系统

- 使用深海军蓝/炭黑中性色面，单一低饱和金色作为重点动作与告警强调色。
- 去除当前蓝色与橙色双主色、均匀渐变和过重发光，保留轻微网格纹理与单一光源阴影。
- 数字使用等宽或 tabular figures；面板使用更紧的内层圆角和更克制的边框。
- 主布局使用 CSS Grid；在中等宽度下降低左右栏宽度，在小屏按设备、视频、告警顺序纵向排列。

## 数据与授权设计

### 摄像头范围传递

`useDashboardData()` 接收响应式的当前设备 ID：

```text
selectedDevice.id
  -> useDashboardData(activeDeviceId)
  -> /video/alert/statistics?device_id=...
  -> /video/alert/page?device_id=...&skip_backfill=1
```

- 没有合法设备 ID 时不请求受摄像头范围保护的告警接口。
- 设备切换立即刷新，并由现有 in-flight guard 防止并发覆盖。
- 告警列表轮询必须传 `{ polling: true }`，使用 30 秒超时、关闭 GET 重试并保持请求去重。

### DEVICE 授权

- 把 `alert_read` 加入 `AuthController.MEDIA_ACTIONS`。
- 为媒体动作提供安全的默认权限映射；`alert_read` 映射到现有告警复核媒体读取权限。
- 仍然要求：有效登录用户、有效租户、明确的摄像头 ID、用户显式摄像头授权和匹配的 RBAC 权限。
- 未授权摄像头继续返回 `camera_scope_denied`，不允许退化为租户全量查询。

### 前端认证头

- 首页接口继续使用 Axios 全局拦截器写入真实 `Authorization: Bearer <token>`。
- 首页告警调用不再依赖遗留的 `localStorage.jwt_token` 或写入 `Bearer null` 的全局 `X-Authorization` 副作用。

## AI 空任务自举设计

### 任务选择顺序

开启 AI 时按以下顺序执行，并保证幂等：

1. 查询实时算法任务。
2. 如果已有覆盖当前设备、已运行并启用告警的非首页任务，直接复用，不创建重复任务。
3. 如果已有同范围的 `[Dashboard Guard]` 任务，启动或复用它。
4. 如果存在其他带模型的实时任务，以它为模板创建首页任务。
5. 如果任务表完全为空，查询模型列表，选择所有可用且具有有效 ID 的模型作为首次自举模型集合。
6. 创建 `[Dashboard Guard] <设备>` 实时任务并启动。

### 默认首页任务

首次自举任务使用：

- `task_type: realtime`
- 当前主画面的同步设备 ID
- 去重后的可用模型 ID
- `alert_event_enabled: true`
- `alert_class_names: []`，表示任意检测可告警
- 全时布防
- `is_enabled: false` 创建后再调用 start，避免半配置运行

若模型列表为空，开关恢复关闭并显示“没有可用模型”，不创建无模型任务。

### 并发与停止规则

- 同一次 AI 开启过程共享一个进行中的启动 Promise，避免 watcher、视频恢复和国标同步同时创建重复任务。
- 关闭 AI 只停止同范围的 `[Dashboard Guard]` 任务。
- 被复用的普通后台任务不由首页关闭。
- 任务创建成功但启动失败时保留任务用于重试，同时把开关恢复关闭并显示后台错误。

### 告警类别兼容

删除“启用告警必须至少配置一个类别”的冲突校验，使服务行为与模型注释和过滤函数一致：

- 类别数组非空：只对命中的类别告警。
- 类别数组为空：任意检测结果都可告警。

## 错误与状态呈现

- 首页数据失败不再连续弹全局错误消息；头部显示接口异常，右栏显示具体原因。
- 403 显示“当前账号无权读取该设备告警”，不显示笼统“调用接口失败”。
- AI 启动失败只显示一次带原因的消息，并把状态标记为失败。
- 部分接口成功时保留上一次成功数据并标记“部分异常”，不把全部统计清零。

## 测试策略

### WEB

- 告警统计与列表都携带当前设备 ID。
- 告警轮询调用 `{ polling: true }`，关闭默认重试。
- 没有有效设备时不调用受保护接口。
- 空任务列表时会加载模型、创建任务并启动。
- 并发启动只创建一个任务。
- 首页仍有唯一 AI 开关和管理后台入口。
- 首页固定单画面，现有视频恢复、AI 流回退和告警回放回归测试继续通过。

### DEVICE

- `alert_read` 是受支持动作。
- 有媒体读取权限和显式摄像头范围时允许。
- 缺租户、缺摄像头、无 RBAC 权限或摄像头越权继续拒绝。

### VIDEO

- 创建与更新任务允许 `alert_event_enabled=true` 且空告警类别。
- 非空类别仍正确序列化并过滤。
- 告警集合接口继续强制 tenant + camera scope。

### 构建与线上验证

- 运行聚焦 WEB、DEVICE、VIDEO 测试。
- 运行 WEB 类型检查、生产构建和差异检查。
- 部署 WEB、iot-system 与 video-service 对应变更。
- 登录后验证首页单画面布局、管理后台跳转、统计/告警 HTTP 200、5 秒单次轮询、AI 任务创建与运行状态。
- 通过 VIDEO 审计确认告警读取为 `allowed`，并确认不再出现 `action_permission_denied`。

## 非目标

- 不新增首页模型选择器。
- 不新增多画面指挥中心。
- 不重做告警处置工作流或监督闭环。
- 不修改无关页面、品牌运行标识、环境键或存储兼容键。
- 不自动停止用户在管理后台创建的算法任务。

## 验收标准

1. 登录后首先进入新的单画面聚焦型指挥中心。
2. 右上角“管理后台”可见、可操作并进入原后台页面。
3. 选中设备后，统计与告警接口返回 HTTP 200，且每 5 秒各最多发起一次轮询请求。
4. 空 `algorithm_task` 数据库状态下开启 AI，可自动创建并启动首页任务。
5. AI 任务启用告警事件，检测结果可进入告警链路。
6. 页面切换回来后视频和 AI 显式选择继续恢复。
7. 现有聚焦测试、类型检查与生产构建通过，公网部署完成后再次验证。
