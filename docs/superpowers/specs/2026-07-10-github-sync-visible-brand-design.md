# GitHub 同步与可见品牌替换设计

## 背景

当前工作分支为 `codex/mf-29-task-accept-controller-clean`。远端 `origin/main` 已抓取到 `8c2af07f`；本地与远端自共同基线 `8eb99e80` 起双向分叉，本地有 145 个提交，远端有 43 个提交。工作区同时保留 8 个受跟踪修改、4 个源码或测试未跟踪文件，以及大量部署包和烟测产物。

合并预演显示 96 个已提交路径两边都改过，其中 28 处需要人工解决冲突。当前 8 个受跟踪修改中有 6 个路径也被远端修改：`VIDEO/models.py`、`VIDEO/run.py`、dashboard 的 `Header.vue`、`Sidebar.vue`、`VideoMonitor.vue` 和 `index.vue`；4 个未跟踪源码/测试路径与远端没有重叠。

## 目标

1. 将 `origin/main` 的最新功能和修复合并到当前本地分支。
2. 完整保留当前未提交源码、测试和部署产物，不使用重置或覆盖式同步。
3. 将页面、应用标题、默认展示值、公开说明和其他用户可见内容中的 `easyaiot` / `EasyAIoT` 品牌替换为 `yFeiEye`。
4. 保持路径、环境变量、网络、服务、存储键、镜像仓库和外部账号等运行契约不变。
5. 用冲突检查、品牌残留测试、模块测试和构建结果证明合并后的代码可用。

## 非目标

- 不改写 145 个本地提交的历史，不做 rebase。
- 不重命名代码包、目录、数据库对象或部署服务。
- 不删除或整理现有部署包、截图及烟测产物。
- 不借本次合并重构无关模块。

## 合并方案

### 1. 精准保护工作区

先记录 `HEAD`、远端提交、完整状态和差异摘要。通过显式路径暂存当前 8 个受跟踪修改及 4 个源码/测试未跟踪文件，其中 6 个受跟踪路径需要在合并后重点核对恢复结果；大量 `deploy-packages/`、`.codex-smoke/` 和截图产物保持原地不动。这样既能清空会影响合并的源码修改，也避免把体积很大的本地产物装入 stash。

### 2. 三方合并远端

使用普通非快进三方合并把 `origin/main` 合入当前分支。对预演发现的 28 处冲突逐文件比较共同基线、本地版本和远端版本：

- 功能代码优先组合两边有效改动，不整文件选择 `ours` 或 `theirs`。
- 本地已有的播放、告警、集群、持久化和 dashboard 修复必须保留。
- 远端新增的算法推理、播放器、通知、部署和自定义平台品牌能力必须吸收。
- 删除/修改冲突根据当前调用关系决定；只有确认远端已移除所有引用时才接受删除。
- 多语言部署文档保留远端最新安装说明，同时继续使用 `yFeiEye` 可见品牌。

解决冲突后，先确认索引中没有未合并条目，再运行与冲突文件对应的检查，然后生成独立的合并提交。

### 3. 恢复本地未提交工作

合并提交完成后重新应用精准 stash。由于 6 个受跟踪路径与远端重叠，恢复阶段预期可能再次产生冲突；此时以“合并后的最新代码、stash 中的原工作区修改、stash 基线”进行三方比较，不丢弃 stash。恢复完成后核对原 12 个源码/测试路径仍在，并保留原有未提交状态。

## 品牌替换边界

### 必须替换

- Vue/TS/HTML 页面中的标题、标签、提示、默认品牌名、图片替代文本和可见模板文本。
- APP 菜单等展示字段；保留同对象中的路由或权限键。
- 登录页、dashboard、平台品牌设置、浏览器标题的默认展示值。
- README、公开部署说明、宣传材料和页面会链接展示的文档标题或正文。
- 后端返回并直接作为品牌展示的默认名称；若字段同时承担协议或匹配用途，则在展示层转换，避免修改协议值。

### 必须保留

- `EASYAIOT_*` 环境变量和兼容配置名。
- `/opt/easyaiot`、`/mnt/easyaiot-media` 等文件系统路径。
- `easyaiot-network`、systemd 服务名、容器名、存储键、MinIO 别名和 Ceph 名称。
- 镜像仓库命名空间、GitHub/Gitee 地址、Badge 地址以及真实外部联系账号。
- 路由、权限、缓存和兼容映射中的 `easyaiot` 键值。
- User-Agent 或第三方协议值，除非验证其仅用于展示且没有兼容性依赖。

## 测试策略

品牌修改遵循测试先行：先增加一个只覆盖用户可见源码和公开文档的品牌残留契约测试，并确认它因远端带回的旧品牌而失败；再做最小替换使其通过。测试中的排除项必须是上述受保护的运行契约，不能用宽泛目录排除掩盖页面残留。

合并和品牌修改至少通过以下验证：

1. `git ls-files -u` 无输出，且源码中不存在冲突标记。
2. 品牌残留契约测试通过；对 `EasyAIoT`、`Easy AI Internet of Things` 和可见小写品牌做补充扫描。
3. 原有 12 个未提交源码/测试路径全部恢复，部署与烟测产物未删除。
4. 对冲突涉及的 Python、Shell、Vue/TypeScript 和 Java 模块运行现有的针对性测试或语法检查。
5. WEB 完整构建通过；Docker Compose 配置和关键安装脚本通过解析/语法检查。
6. `git diff --check`、`git diff --cached --check` 无错误。
7. 最终提交图包含 `origin/main@8c2af07f`，并记录合并后的本地 `HEAD`。

## 异常处理

- 合并冲突超出预演范围时，暂停提交并逐项记录新增冲突，仍采用共同基线、本地、远端三方比较。
- 测试失败时先区分远端基线问题、冲突解决问题和本地未提交改动问题；不通过删除本地改动来获得绿色结果。
- stash 恢复失败时保留 stash 引用，直到已核对所有受保护路径；不使用 `git reset --hard`、`git clean` 或覆盖式 checkout。
- 如果某个旧品牌字符串既会显示又承担运行契约，保留底层值并在现有展示边界转换为 `yFeiEye`。

## 完成标准

远端 43 个提交已进入当前分支；28 处预演冲突及实际新增冲突均已人工解决；原工作区修改和产物仍在；用户可见品牌统一为 `yFeiEye`；受保护的技术标识保持兼容；针对性测试、品牌契约、WEB 构建和 Git 完整性检查均给出新鲜通过证据。
