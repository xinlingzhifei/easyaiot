## Обзор

yFeiEye — это платформа облачно-периферийных интеллектуальных алгоритмических приложений, использующая единый скрипт установки для развертывания в один клик. Платформа поддерживает контейнеризированное развертывание через Docker и позволяет быстро установить и запустить все сервисные модули.

### Архитектура платформы

Платформа yFeiEye состоит из следующих ключевых модулей:

- **Базовые сервисы** (`.scripts/docker`): Включают промежуточное ПО, такое как Nacos, PostgreSQL, Redis, TDEngine, Kafka, MinIO и другие.
- **DEVICE сервис**: Сервис управления устройствами и шлюза (на основе Java).
- **AI сервис**: Сервис обработки искусственного интеллекта (на основе Python).
- **VIDEO сервис**: Сервис обработки видео (на основе Python).
- **WEB сервис**: Веб-интерфейс (на основе Vue).

## Требования к окружению

### Системные требования

- **Операционная система**:
   - Linux (рекомендуется Ubuntu 24.04)
   - macOS (рекомендуется macOS 10.15+)
   - Windows (рекомендуется Windows 10/11, требуется PowerShell 5.1+)
- **Память**: Рекомендуется 32 ГБ (минимум 16 ГБ)
- **Дисковое пространство**: Рекомендуется 200 ГБ и более свободного места
- **CPU**: Рекомендуется 8 ядер (минимум 4 ядра)
- **Видеокарта**: Рекомендуется NVIDIA GPU (минимум CPU)

### Программные зависимости

Перед запуском скрипта развертывания убедитесь, что установлено следующее ПО:

1. **Docker** (обязательная версия v29.0.0+)
   - Инструкция по установке: https://docs.docker.com/get-docker/
   - Проверка установки: `docker --version`
   - **Важно**: Версия Docker должна быть v29.0.0 или выше, более ранние версии не будут работать корректно.

2. **Docker Compose** (обязательная версия v2.35.0+)
   - Инструкция по установке: https://docs.docker.com/compose/install/
   - Проверка установки: `docker compose version`
   - **Важно**: Версия Docker Compose должна быть v2.35.0 или выше, более ранние версии не будут работать корректно.

3. **Прочие зависимости**:
   - **Linux/macOS**: `curl` (используется для проверки работоспособности, обычно предустановлен в системе)
   - **Windows**: PowerShell 5.1+ (обычно предустановлен в системе)

### Настройка прав доступа Docker

#### Linux

Убедитесь, что текущий пользователь имеет доступ к Docker daemon:

```bash
# Способ 1: Добавить пользователя в группу docker (рекомендуется)
sudo usermod -aG docker $USER
# Затем перелогиньтесь или выполните
newgrp docker

# Способ 2: Запускать скрипт через sudo (не рекомендуется)
sudo ./install_linux.sh [команда]
```

Проверка прав доступа Docker:

```bash
docker ps
```

#### macOS

В macOS обычно не требуется специальной настройки прав, Docker Desktop обрабатывает их автоматически.

#### Windows

В Windows Docker Desktop также автоматически обрабатывает права, но при необходимости убедитесь, что PowerShell запущен от имени администратора.

## Быстрый старт

### Развертывание в Linux

#### 1. Получение кода проекта

```bash
# Клонирование проекта (если еще не сделано)
git clone <repository-url>
cd yfeieye
```

#### 2. Переход в директорию со скриптами

```bash
cd .scripts/docker
```

#### 3. Выдача прав на выполнение скрипта

```bash
chmod +x install_linux.sh
```

#### 4. Установка всех сервисов в один клик

```bash
./install_linux.sh install
```

Эта команда выполнит:
- Проверку окружения Docker и Docker Compose
- Создание единой сети `yfeieye-network`
- Установку всех модулей в порядке зависимостей
- Запуск всех сервисных контейнеров

#### 5. Проверка статуса сервисов

```bash
./install_linux.sh verify
```

Если все сервисы работают нормально, будут показаны адреса для доступа к ним.

## Инструкция по использованию скриптов

### Расположение скриптов

Единые скрипты установки находятся в директории `.scripts/docker/` корня проекта:

- **Linux**: `install_linux.sh`
- **macOS**: `install_mac.sh`
- **Windows**: `install_win.ps1`

### Доступные команды

Все операционные системы поддерживают одинаковые команды, но имена скриптов различаются:

| Команда | Описание | Пример для Linux | Пример для macOS | Пример для Windows |
|---------|----------|------------------|------------------|--------------------|
| `install` | Установить и запустить все сервисы (первый запуск) | `./install_linux.sh install` | `./install_mac.sh install` | `.\install_win.ps1 install` |
| `start` | Запустить все сервисы | `./install_linux.sh start` | `./install_mac.sh start` | `.\install_win.ps1 start` |
| `stop` | Остановить все сервисы | `./install_linux.sh stop` | `./install_mac.sh stop` | `.\install_win.ps1 stop` |
| `restart` | Перезапустить все сервисы | `./install_linux.sh restart` | `./install_mac.sh restart` | `.\install_win.ps1 restart` |
| `status` | Посмотреть статус всех сервисов | `./install_linux.sh status` | `./install_mac.sh status` | `.\install_win.ps1 status` |
| `logs` | Посмотреть журналы всех сервисов | `./install_linux.sh logs` | `./install_mac.sh logs` | `.\install_win.ps1 logs` |
| `build` | Пересобрать все образы | `./install_linux.sh build` | `./install_mac.sh build` | `.\install_win.ps1 build` |
| `clean` | Очистить все контейнеры и образы (опасная операция) | `./install_linux.sh clean` | `./install_mac.sh clean` | `.\install_win.ps1 clean` |
| `update` | Обновить и перезапустить все сервисы | `./install_linux.sh update` | `./install_mac.sh update` | `.\install_win.ps1 update` |
| `verify` | Проверить, успешно ли запущены все сервисы | `./install_linux.sh verify` | `./install_mac.sh verify` | `.\install_win.ps1 verify` |

## Описание модулей

**Описание**: Содержат все необходимые промежуточные сервисы для работы платформы.

- **Nacos**: Сервис регистрации и конфигурации.

## Частые проблемы

### 1. Проблемы с правами доступа Docker

**Проблема**: При выполнении скрипта выводится сообщение "Нет прав доступа к Docker daemon".

**Решение**:

**Linux**:
```bash
# Добавить пользователя в группу docker
sudo usermod -aG docker $USER

# Перелогиньтесь или выполните
newgrp docker

# Проверка прав
docker ps
```

**macOS**:
В macOS обычно не требуется специальной настройки, просто убедитесь, что Docker Desktop запущен.

**Windows**:
В Windows Docker Desktop автоматически обрабатывает права, убедитесь, что Docker Desktop запущен.

### 2. Занятость порта

**Проблема**: При запуске сервиса выводится сообщение, что порт уже занят.

**Решение**:

**Linux**:
```bash
# Проверить, какой процесс занимает порт
sudo netstat -tulpn | grep <номер порта>
# или
sudo lsof -i :<номер порта>

# Остановить процесс, занимающий порт, или изменить порт в конфигурации сервиса
```

**macOS**:
```bash
# Проверить, какой процесс занимает порт
lsof -i :<номер порта>

# Остановить процесс, занимающий порт, или изменить порт в конфигурации сервиса
```

**Windows**:
```powershell
# Проверить, какой процесс занимает порт
netstat -ano | findstr :<номер порта>

# Остановить процесс, занимающий порт, или изменить порт в конфигурации сервиса
```

### 3. Сбой запуска сервиса

**Проблема**: Не удается запустить какой-либо сервисный модуль.

**Решение**:

**Linux/macOS**:
```bash
# 1. Посмотреть журналы сервисов
./install_linux.sh logs    # Linux
./install_mac.sh logs      # macOS

# 2. Посмотреть подробные журналы конкретного модуля
cd <директория модуля>
docker-compose logs

# 3. Проверить ресурсы Docker
docker ps -a
docker images

# 4. Проверить сеть
docker network ls
docker network inspect yfeieye-network
```

**Windows**:
```powershell
# 1. Посмотреть журналы сервисов
.\install_win.ps1 logs

# 2. Посмотреть подробные журналы конкретного модуля
cd <директория модуля>
docker-compose logs

# 3. Проверить ресурсы Docker
docker ps -a
docker images

# 4. Проверить сеть
docker network ls
docker network inspect yfeieye-network
```

### 4. Сбой сборки образа

**Проблема**: Сбой при сборке образа.

**Решение**:

**Linux/macOS**:
```bash
# 1. Проверить дисковое пространство Docker
docker system df

# 2. Очистить неиспользуемые ресурсы
docker system prune -a

# 3. Проверить сетевое подключение (если требуется загрузка базовых образов)
ping registry-1.docker.io

# 4. Собрать образ для модуля отдельно
cd <директория модуля>
```

### 6. Потеря данных

**Проблема**: Потеря данных после очистки сервисов.

**Пояснение**: Команда `clean` удаляет все тома данных, что приводит к потере данных. Это ожидаемое поведение.

**Меры предосторожности**:
- Сделайте резервную копию важных данных перед выполнением `clean`.
- Используйте команду `clean` с осторожностью в рабочей среде.
- Рекомендуется использовать инструменты резервного копирования томов данных.

## Управление журналами

### Расположение файлов журналов

Журналы выполнения скриптов сохраняются в директории `.scripts/docker/logs/`:

- **Linux**: `install_linux_YYYYMMDD_HHMMSS.log`
- **macOS**: `install_mac_YYYYMMDD_HHMMSS.log`
- **Windows**: `install_win_YYYYMMDD_HHMMSS.log`

Имя файла журнала содержит временную метку для удобного различения записей различных выполнений.

### Просмотр журналов

#### Просмотр журналов выполнения скриптов

**Linux/macOS**:
```bash
# Посмотреть последние файлы журналов
ls -lt .scripts/docker/logs/ | head -5

# Посмотреть конкретный файл журнала
tail -f .scripts/docker/logs/install_linux_20240101_120000.log    # Linux
tail -f .scripts/docker/logs/install_mac_20240101_120000.log      # macOS
```

**Windows**:
```powershell
# Посмотреть последние файлы журналов
Get-ChildItem .scripts\docker\logs\ | Sort-Object LastWriteTime -Descending | Select-Object -First 5

# Посмотреть конкретный файл журнала
Get-Content .scripts\docker\logs\install_win_20240101_120000.log -Wait
```

#### Просмотр журналов сервисных контейнеров

**Linux/macOS**:
```bash
# Посмотреть журналы всех сервисов
./install_linux.sh logs    # Linux
./install_mac.sh logs      # macOS

# Посмотреть журналы конкретного сервиса (требуется перейти в директорию модуля)
cd DEVICE
docker-compose logs -f
```

**Windows**:
```powershell
# Посмотреть журналы всех сервисов
.\install_win.ps1 logs

# Посмотреть журналы конкретного сервиса (требуется перейти в директорию модуля)
cd DEVICE
docker-compose logs -f
```

### Содержимое журналов

Журналы скриптов содержат:
- Временную метку выполнения.
- Выполненные команды.
- Результаты выполнения каждого модуля.
- Сообщения об ошибках и предупреждениях.
- Информацию о статусе сервисов.

## Важные замечания

1. **Требования к версиям**: **Обязательно** установите Docker v29.0.0+ и Docker Compose v2.35.0+, более ранние версии не будут работать корректно.
2. **Сетевые требования**: Убедитесь, что сервер имеет доступ к Docker Hub или настроенному реестру образов.
3. **Требования к ресурсам**: Убедитесь, что у сервера достаточно CPU, памяти и дискового пространства.
4. **Конфликт портов**: Убедитесь, что необходимые порты не заняты другими сервисами.
5. **Резервное копирование данных**: Перед развертыванием в рабочей среде создайте резервные копии важных данных.
6. **Настройка безопасности**: В рабочей среде настройте правила брандмауэра и групп безопасности.
7. **Управление журналами**: Регулярно очищайте старые файлы журналов, чтобы избежать нехватки дискового пространства.
